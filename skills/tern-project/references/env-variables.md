# Tern 运行变量清单（env.variables）设计指南

变量清单是用例仓库对平台的**契约**：声明本项目运行需要哪些变量。清单在仓库（`tern.yaml` 的 `env:` 节点）；有哪些环境、每个环境的**值**在平台侧配置（Web 项目页「环境」或 `tern env create`，secret 值加密存储不回显）；发起运行时按环境名引用。

## 判定规则

一条主规则 + 两条补充：

1. **换一个环境（dev → test → staging → prod），这个值会不会变？会变 → 变量。**
2. **凭据即使所有环境都相同，也必须走变量**——因为真实值不能进 git（清单/用例里只允许出现 `${ENV:VAR}` 占位符）。
3. **用例或 auth 配方里读了 `process.env.X` / `${ENV:X}`，X 就应该出现在清单里**——否则平台无法帮你校验环境是否配齐，缺值只会在执行期静默失败。

## 变量分类

### 1. 地址类（几乎必有）

| 变量           | 说明                                                                                                                                            |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `BASE_URL`     | **被测系统入口地址**（前端/门户）。平台自动将其作为 Playwright `baseURL`；auth 配方里的相对地址也用它拼接。E2E 的「测什么」就由它决定，**必有** |
| `API_BASE_URL` | 可选。用例需要**直调后端 API**（绕过前端代理）或前后端分域部署时声明                                                                            |
| 其他依赖地址   | 可选。用例实际依赖的第三方服务（文件服务、验证码服务、mock 服务）地址，用到才加                                                                 |

### 2. 凭据类（`secret: true`）

auth 配方 `accounts` 里引用的所有 `${ENV:VAR}`，**每个身份一个**：

- 接口登录的 clientId / token（如接口凭据 `CLIENT_ID`、`ADMIN_CLIENT_ID`）；
- 表单登录的用户名/密码（`USERNAME` / `PASSWORD`）；
- storage 直写的长期 token（`TOKEN`）。

特征：值只在平台加密存储、API 永不回显、不进 git、不落报告。

### 3. 环境特征 / 数据类（可选，按需）

随环境不同、但既不是地址也不是凭据的输入：

- **租户 / 设备 / 组织 ID**：多租户系统里各环境数据不同（如多租户业务下的 `TENANT_ID` / `DEVICE_ID`，换环境即换值，天然属于凭据或环境配置类）；
- **功能开关**：某环境未部署某模块时，用例读取后显式跳过（如 `FEATURE_REPORTS=off`）——比用例猜着超时失败清晰得多；
- **测试数据定位**：各环境预置的不同测试数据（测试订单编号、固定上传文件等）；
- **慢环境标志**：联调/弱网环境放宽等待（如 `SLOW_ENV=true`，用例据此放大 timeout）——谨慎使用，别让它成为用例不稳定的遮羞布。

## 反例：不该放进变量的东西

- **选择器、断言预期文案**：是用例逻辑，不随环境变（预期值随环境数据变时，应变量的是「数据定位」而不是断言本身）；
- **与环境无关的超时/重试**：归用例 frontmatter（`timeout` / `retries`）；
- **平台自身配置**（WORKER_TOKEN、并发槽等）：与项目用例无关。

## 必填语义：进清单 = 每个环境必须配齐

清单中声明的变量，平台会**强制每个环境配齐**（缺值在创建运行时即报错并列出缺失键）。因此：

- **希望 fail-fast 的输入 → 进清单**（推荐：地址、凭据这类缺了必死的输入）；
- **真正可选的输入 → 不进清单**，用例里 `process.env.X ?? 默认值` 自给默认（平台不校验，灵活但缺值不会提前暴露）；
- 功能开关建议**进清单**：迫使每个环境显式表态（`on`/`off`），而不是默默走默认。

## 完整示例

```yaml
env:
  variables:
    # 地址类
    BASE_URL:
      description: 门户前端地址（/api 由其代理到后端）
    API_BASE_URL: # 用例直调后端时才需要
      description: 后端 API 地址
    # 凭据类（secret）
    CLIENT_ID:
      description: default 账号 clientId
      secret: true
    ADMIN_CLIENT_ID:
      description: admin 账号 clientId
      secret: true
    # 环境特征类（按需）
    TENANT_ID:
      description: 租户 ID（各环境预置数据不同）
    FEATURE_REPORT:
      description: 报表模块开关（环境未部署置 off，用例据此跳过）
```

用例侧读取：`BASE_URL` 自动生效；其余 `process.env.TENANT_ID`、`process.env.FEATURE_REPORT === 'off'` 时跳过；auth 配方侧 `${ENV:CLIENT_ID}`。运行时统一引用环境：`tern run --project portal --env staging --wait`（运行参数显式传入优先于环境值）。
